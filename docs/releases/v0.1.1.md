# v0.1.1 release notes

Date: 2026-09-28.

## Change

`codex-task-authoring` now completes an authorized specification when the only missing details belong to an unchanged, established convention. It references that convention rather than inventing or redesigning it. A conflict that changes the required scope, permission, persistence, public contract, or observable behavior still stops authoring for one focused question; the question identifies its effect on the deliverable. Explicit user instructions take precedence over skill defaults, subject to higher-priority instructions. Review-mode findings end with one focused question about the highest-impact unresolved decision rather than bundling several questions. Modes, profiles, output format, and invocation metadata are unchanged.

## Evidence

The repository contract suite and official Skill Creator validator passed. Across eight blind fixtures per model (GPT-6 Astra and GPT-6 Sol), each had seven full passes and one partial result on the latest outputs. The Review fixtures and blocking ambiguity were rerun after the final mode-boundary edit. The permission-conflict case asked the correct blocking question but did not explicitly state that dialog wording is non-blocking; An earlier Sol sample switched to Russian despite English fixture input; the final sample used English. The other cases covered frontend, backend, fullstack/API delta, reviews with and without a blocker, unchanged-convention reuse, and explicit user-instruction priority. Earlier Sol Review samples sometimes placed the correct question inside findings rather than at the end; the latest sample ended with the question. A separate metadata-only trigger audit classified 10/10 examples as expected on both GPT-6 Luna and Astra; actual Codex implicit activation was not verified. See [forward-test evidence](../../tests/forward-test-report.md) for methodology and limitations. Static checks cannot prove model behavior.
